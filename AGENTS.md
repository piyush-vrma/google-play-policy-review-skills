# AGENTS.md

## Repository Mission: Master Google Play Store Policy Review Skill

This repository is dedicated to creating, maintaining, and benchmarking the definitive, production-grade **Google Play Store Policy Review & Remediation Skill** (`google-play-policy-review`).

The master skill unifies and supersedes three high-value reference implementations:
1. **`google-play-policy-guardian-2026`** (`referenceskills/google-play-policy-guardian-2026`): 
   - 2026 policy baseline & live web search sync protocol (Phase 0).
   - Comprehensive coverage of 2026 enforcement shifts: 180-day appeal hard window, formal Plan of Action (POA) appeals, AI-driven identity association bans, AdMob IAB TCF v2.3 compliance, Contacts/Location button changes, and self-update logging.
2. **`google-play-policy-remediation`** (`referenceskills/google-play-policy-remediation`):
   - Principal Android Engineer and Google Play Reviewer persona.
   - Strict classification system: `Confirmed violation`, `Policy risk`, `Needs Play Console verification`, `Not applicable`.
   - Precise source code citation (file and line numbers).
   - Safe, non-speculative remediation standards preserving data migrations and preventing arbitrary rewrites.
   - Distinct separation between code-level audits and Play Console requirements (declarations, Data Safety form, store listings).
3. **`playstore-review`** (`.agents/skills/playstore-review`):
   - Universal multi-framework detection and analysis across 9 ecosystems: Native (Kotlin/Java), Flutter, React Native, Expo (Managed & Bare), Kotlin Multiplatform (KMP), .NET MAUI, Cordova/Ionic, Capacitor, and Unity.
   - Deep merged-manifest awareness (SDK-injected permissions and components).
   - Comprehensive monetization checks (Play Billing for digital goods vs third-party billing for physical goods, subscription transparency).
   - Step-by-step audit rubric with top 10 Play rejection quick checks.

## Architectural Standard: `skill-creator` Specification

All skills developed in this repository must strictly adhere to the Anthropics `skill-creator` architecture:

### 1. Progressive Disclosure Model
- **Level 1: Metadata (YAML Frontmatter)**
  - Name and high-intent, descriptive summary.
  - Triggering phrases must be comprehensive and proactive ("pushy") so LLMs trigger appropriately across varied user phrasing (pre-submission review, app rejection, policy warnings, AdMob issues, account recovery).
- **Level 2: Skill Body (`SKILL.md`)**
  - Kept concise (target < 500 lines).
  - Contains core workflow orchestration, triage logic, classification rules, and operational execution steps.
- **Level 3: Bundled Modular Resources**
  - `references/`: In-depth domain and framework documentation read into context on-demand (e.g. core policy areas, ads & monetization, framework-specific guides, appeal & recovery blueprints).
  - `scripts/`: Deterministic checks, manifest parsers, or policy verification helpers where appropriate.
  - `evals/`: Benchmarking test suites, realistic prompts, and assertion criteria to test skill triggering and auditing quality.

## Policy Baseline & Realities (2026 Edition)

Every audit and recommendation generated by the skill must be anchored in current Google Play enforcement realities:

1. **Target SDK Requirements & Rolling Rule**:
   - Rolling 1-year rule: Apps submitted must target an API level within 1 year of the latest stable Android release.
   - API 35 (Android 15) hard minimum; API 36 (Android 16) / API 37 (Android 17, released June 2026) accepted and recommended.
2. **Permissions & Restricted APIs**:
   - Photo/Video Picker: `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO` prohibited if the system photo picker (`PickVisualMedia`) suffices.
   - Contacts: Android 17+ Contact Picker required; `READ_CONTACTS` requires special declaration.
   - Location: One-time access requires Location Button; background location requires rigorous core-functionality justification and demo video.
   - Accessibility API: Autonomous AI agents using `AccessibilityService` are strictly prohibited.
   - SMS/Call Log, `QUERY_ALL_PACKAGES`, `MANAGE_EXTERNAL_STORAGE`: Allowed only for declared narrow exception categories.
3. **Monetization & Ads**:
   - Google Play Billing v7+ required for digital goods/services; external payment processors permitted only for physical goods.
   - AdMob IAB TCF v2.3 compliance required for EU/EEA/UK traffic; UMP SDK updated.
   - Ads strictly forbidden on splash screens, lock screens, notification shade, or covering interactive elements. Interstitials must be closeable within 15 seconds.
4. **Families & Children (COPPA)**:
   - Zero advertising ID (`AD_ID`) for child-directed apps; only Families Self-Certified Ads SDKs with COPPA treatment flags enabled.
   - Neutral age screening required for mixed-audience apps.
5. **Account Termination & Recovery (180-Day Rule)**:
   - Strict 180-day deadline from termination notice to submit formal appeals.
   - Formal **Plan of Action (POA)** structure mandatory (hardware audit, network audit, identity verification, app-by-app policy remediation, compliance commitment).

## Operating Persona & Directives for AI Agents

When executing audits or remediating code using the master skill:
- **Persona**: Act as a Principal Android Engineer, Google Play Policy Specialist, and Security Auditor.
- **Evidence-First**: Always cite exact file paths and line numbers.
- **No False Assurances**: Never guarantee Play Store approval. Clearly communicate that console declarations, store listings, Data Safety forms, and developer account standing ultimately decide approval.
- **Systematic Classification**:
  - `Confirmed violation`: Clear breach in source code or configuration.
  - `Policy risk`: Code patterns that raise flags during Google Play automated/manual reviews.
  - `Needs Play Console verification`: Setting or requirement that cannot be verified from the codebase alone.
  - `Not applicable`: Policy check reviewed and irrelevant to this app.
- **Safe Remediation**: Never perform speculative refactoring. Preserve data persistence with migrations. Include test coverage for compliance fixes.
